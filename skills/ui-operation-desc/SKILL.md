# 畫面操作說明

把指定範圍的程式碼，寫成**不寫這段程式的對口也看得懂的畫面操作說明**。給 PM、QA、其他單位 RD 對齊「使用者在畫面上做什麼、為什麼做」。

讀 [`CONTEXT.md`](CONTEXT.md)：選文件種類，並套用 **去實作化**、**畫面用詞**、**清單寫完整**、**畫面動詞**、**畫面名不是所有格**。事實只來自程式碼。指定文件只用來圈定要讀哪些程式碼。

每個指定範圍產出一篇，固定三塊：

> 使用者操作目的
> 使用者操作流程
> 相關聯的畫面

若使用者要的是測試項目 → 讀 [test-item](../test-item/SKILL.md)。
若使用者要的是需求規格（給後端）→ 讀 [fe-code-to-api-requirement](../fe-code-to-api-requirement/SKILL.md)。
若使用者要的是 TD Detail → 讀 [td-detail-fillin](../td-detail-fillin/SKILL.md)。

## Trigger

使用者要為**自己指定的文件與／或程式碼範圍**產生／改寫畫面操作說明時套用。

範圍不明、或只給文件沒給程式碼：先問，不要寫。

## 本文件獨有的硬規則（違反即重寫）

1. **事實只來自程式碼。** 證據鏈必須是：指定範圍 → 使用者指出的程式碼。讀過程式碼才能下筆。指定文件只拿來找出要讀哪些檔案／函數；不得把文件敘述、標題、或註解當用途。程式碼與指定文件衝突時，以程式碼為準；交付正文不寫差異表。衝突大到範圍可能指錯時，先問再寫。
2. **目的是使用者打開畫面後想完成的事**（CONTEXT.md **實際**）。「把篩選對應到後端條件」「消費 catalog」「收斂推算」是重構動機，不是使用者操作目的。

標題是一句畫面摘要（CONTEXT.md **畫面摘要**），不是三區塊的替代品。

## Workflow

複製並勾進度：

```
- [ ] 1. 圈定指定範圍
- [ ] 2. 讀程式碼抽事實
- [ ] 3. 對畫面文案／i18n 核對用詞
- [ ] 4. 列出觀察到的畫面
- [ ] 5. 去實作化後寫標題與三區塊
- [ ] 6. 輸出
```

### 1. 圈定指定範圍

確認使用者指出的文件與／或程式碼。沒有程式碼就不寫，先要路徑。

指定文件若含檔案／函數／行號，用它們去定位程式碼，**仍只讀那些程式碼**，不要抄文件裡的用途敘述。

一篇必須能寫成單一「使用者操作目的」。寫不成就停下來問是否縮小範圍。

### 2. 讀程式碼抽事實

打開真實檔案，抽進草稿（草稿可含實作名，正文不行）：

- 使用者能點什麼、選什麼、送出什麼
- 畫面上會出現什麼文字／數字／清單／空狀態
- 什麼條件下清單或狀態會變
- 這段 UI 掛在哪個畫面／分頁

程式碼看不出使用者操作的片段：不要寫進標題與三區塊，也不要發明一個用途來填空。

只寫這段程式碼覆蓋到的操作。範圍外的兄弟行為不要寫進來。

### 3. 對畫面文案／i18n 核對用詞

標題與正文出現的每個產品詞，必須能在畫面或該範圍程式碼實際引用的 i18n 找到對應文案（CONTEXT.md **畫面用詞**）。

中文標題與正文用繁中畫面文案。對不到畫面詞：停下來問，不要自創，也不要從指定文件借詞。

### 4. 列出觀察到的畫面

「相關聯的畫面」只列程式碼實際掛載、使用者實際進入的畫面／分頁名稱，與畫面標籤一致。沒有預設閉合清單。無法從程式碼判到任何畫面時，停下來問，不要猜。

### 5. 去實作化後寫標題與三區塊

套用 CONTEXT.md **去實作化**。每條草稿問：使用者在哪個畫面、做了什麼、看到什麼？寫不出來的刪掉。標題用同一句畫面摘要。

### 6. 輸出

- 指定路徑 → 寫入該 markdown。
- 未指定 → 寫在對話中。
- 一個指定範圍一篇；不要自行切成多段，除非使用者要求。

完成條件：已寫入或已輸出，且交件前 Checklist 全勾。

## 輸出格式

每篇 **只准**這三個內容區塊（區塊標題用詞固定）。段前 `##` 用一句畫面摘要。

```markdown
## （一句畫面摘要）

### 使用者操作目的
（2–4 句。誰、在哪個畫面、想完成什麼。不要寫重構／API／收斂。）

### 使用者操作流程
1. （單一動作：進入哪個畫面或打開哪個畫面）
2. （單一動作：點選、篩選、或送出）
3. （單一動作：畫面上出現什麼結果）

### 相關聯的畫面
- （從程式碼觀察到的畫面／分頁名，原樣列出）
```

流程規則：

- 用編號步驟；一步一個動作。
- 只寫指定程式碼實際覆蓋的路徑；不要為了「完整」補沒讀到的步驟。
- 多個畫面時，流程寫清楚各步驟落在哪個畫面；不要假裝只有一條路。

畫面規則：

- 「相關聯的畫面」每行一個名稱，與畫面標籤一致。
- 沒證據的畫面不要列。

缺證據就不要寫那句。

## Example

**不合格**（帶實作詞、自創詞、畫面用元件名、把範圍外行為捲進來）：

```
## applyLicenseFilter() 把 ACTIVE 授權寫入篩選集合

### 使用者操作目的
收斂 compound filter，讓 FE 的 applyLicenseFilter 改由 Inventory API 下發。

### 使用者操作流程
1. 呼叫 QueryOrgInventoryV15
2. 執行 applyLicenseFilter()

### 相關聯的畫面
- inv-device-list
```

**合格**（標題與正文都只用畫面詞；事實來自指定範圍的清單篩選程式碼）：

```
## 使用 Gold Security Pack 的裝置可被 NCC license、Nebula Professional Pack、Secure WiFi 篩選找到

### 使用者操作目的
在 Devices 分頁的表格用授權狀態篩選裝置時，使用 Gold Security Pack 的裝置要能被 NCC license、Nebula Professional Pack、Secure WiFi 的篩選條件找到。

### 使用者操作流程
1. 進入 License & inventory，打開 Devices 分頁
2. 在 Devices 分頁的表格選擇 License type 與 License state
3. Devices 分頁的表格顯示符合該 License type 與 License state 的裝置；使用 Gold Security Pack 而被算進該條件的裝置一併顯示

### 相關聯的畫面
- Devices
```

畫面上寫 Gold Security Pack、NCC license 就用那些詞。指定範圍沒覆蓋到的行為不要寫。
