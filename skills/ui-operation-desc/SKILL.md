# 畫面操作說明

把指定範圍的程式碼，寫成**不寫這段程式的對口也看得懂的畫面操作說明**。給 PM、QA、其他單位 RD 對齊「使用者在畫面上做什麼、為什麼做」。

事實只來自程式碼。指定文件只用來圈定要讀哪些程式碼，不能當證據、也不能借詞。

正文必須去實作化：不可以有當前 API 或程式碼詞彙。不要自創詞彙；只用一般使用者在 UI 上看得到的詞。

用語見根目錄 [`CONTEXT.md`](../../CONTEXT.md)。

每個指定範圍產出一篇，固定三塊：

> 使用者操作目的
> 使用者操作流程
> 相關聯的畫面

## Trigger

使用者要為**自己指定的文件與／或程式碼範圍**產生／改寫畫面操作說明時套用。

範圍不明、或只給文件沒給程式碼：先問，不要寫。

## 與相鄰 skill 的差異（先選對）

| | 本 skill | `fe-code-to-api-requirement` | `td-detail-fillin` |
|---|---|---|---|
| 範圍 | 使用者指定的程式碼（文件只圈範圍） | 某個畫面／功能 | 單條 TD 的 Detail |
| 讀者 | 不寫這段程式的對口 | 要重新討論 API 的後端 | 要對齊既有 API 的 BE RD |
| 正文可否出現現行 API 欄位路徑 | **禁止** | **禁止** | **必寫** |
| 產出 | 三個固定區塊（目的／流程／畫面） | 需求規格 | TD Detail |

- 要寫給後端的 API 需求規格 → `fe-code-to-api-requirement`。
- 要寫 TD Detail 或對齊既有 API → `td-detail-fillin`。

## 七條硬規則（違反即重寫）

1. **事實只來自程式碼。** 證據鏈必須是：指定範圍 → 使用者指出的程式碼。讀過程式碼才能下筆。指定文件只拿來找出要讀哪些檔案／函數；不得把文件敘述、標題、或註解當用途。程式碼與指定文件衝突時，以程式碼為準；交付正文不寫差異表。衝突大到範圍可能指錯時，先問再寫。
2. **標題與正文零實作詞彙。** 不可以有當前 API 或程式碼的詞彙：端點、方法、參數、欄位路徑、payload、變數名、函數名、類別名、元件名、檔案路徑、enum／常數字面值、狀態管理容器名。程式碼證據只留在分析草稿。
3. **不自創詞彙。** 按鈕、分頁、欄位標題、篩選選項、狀態文字、提示——只用畫面上使用者看得到的詞。畫面沒有的詞，不要另造一個「比較專業」的名字；寫不出畫面詞就代表這句不是使用者操作，刪掉或回頭重讀程式碼／i18n。
4. **不寫實作目的。** 「把篩選對應到後端條件」「消費 catalog」「收斂推算」都是重構動機，不是使用者操作目的。目的必須是使用者打開畫面後想完成的事。
5. **不寫模糊省略。** 禁止用來省略項目的寫法：等等、等、同上、同上所述、類似、之類、以上、前述、其他。清單必須從程式碼／i18n 寫完整；寫不完整就回去重讀，不要用省略詞充數。
6. **不用口語，動詞要明確。** 禁止：用得上、搞、弄。可用動詞：接受、使用、選擇、篩選、顯示、進入、點選。
7. **畫面／分頁名不可當所有格簡寫。** 畫面名是畫面；畫面上的物件是物件。禁止寫「{畫面} 的 {欄位}」——讀者會以為是物件本身。定位畫面時必須寫完整：畫面名後面接「分頁」或「畫面」；講表格時寫「{畫面} 分頁的表格」；講欄位時寫「{畫面} 分頁的表格，{欄位} 欄」。

| 禁止 | 改寫 |
|---|---|
| 在 {畫面} 的 {欄位} | 在 {畫面} 分頁的表格，{欄位} 欄 |
| 在 {畫面 A} 與 {畫面 B} 篩選 | 在 {畫面 A} 分頁與 {畫面 B} 分頁篩選 |
| {畫面} 顯示一列 | {畫面} 分頁的表格顯示一列 |

標題是一句畫面摘要，不是三區塊的替代品。不要貼檔名、函數名、或指定文件的原標題。

## Workflow

複製並勾進度：

```
- [ ] 1. 圈定指定範圍
- [ ] 2. 讀程式碼抽事實
- [ ] 3. 對畫面文案／i18n 核對用詞
- [ ] 4. 列出觀察到的畫面
- [ ] 5. 去實作化後寫標題與三區塊
- [ ] 6. 交件前 Checklist
```

### 1. 圈定指定範圍

確認使用者指出的文件與／或程式碼。沒有程式碼就不寫，先要路徑。

指定文件若含檔案／函數／行號，用它們去定位程式碼，**仍只讀那些程式碼**，不要抄文件裡的用途敘述。

一篇必須能寫成單一「使用者操作目的」。寫不成就停下來問是否縮小範圍。

### 2. 讀程式碼抽事實

打開真實檔案，抽進草稿（草稿可含實作名，正文不行）：

- 使用者能點什麼、選什麼、送出什麼
- 畫面上會出現什麼文字／數字／清單／空狀態
- 什麼條件下清單或狀態會變
- 這段 UI 掛在哪個畫面／分頁

程式碼看不出使用者操作的片段：不要寫進標題與三區塊，也不要發明一個用途來填空。

只寫這段程式碼覆蓋到的操作。範圍外的兄弟行為不要寫進來。

### 3. 對畫面文案／i18n 核對用詞

標題與正文出現的每個產品詞，必須能在畫面或該範圍程式碼實際引用的 i18n 找到對應文案。

中文標題與正文用繁中畫面文案。對不到畫面詞：停下來問，不要自創，也不要從指定文件借詞。

### 4. 列出觀察到的畫面

「相關聯的畫面」只列程式碼實際掛載、使用者實際進入的畫面／分頁名稱，與畫面標籤一致。沒有預設閉合清單。無法從程式碼判到任何畫面時，停下來問，不要猜。

### 5. 去實作化後寫標題與三區塊

每條草稿問：「拿掉 API／函數／欄位名之後，使用者在哪個畫面、做了什麼、看到什麼？」寫不出來的刪掉。標題用同一句畫面摘要。

| 草稿（禁止進標題與正文） | 標題／正文 |
|---|---|
| 判斷 `status === ACTIVE` | 清單只留下狀態為有效的項目（沿用畫面狀態文案） |
| UI filter → API 條件映射 | 使用者選好篩選條件後，清單只顯示符合條件的項目 |
| 把畫面「授權有效」改寫成「許可憑證生命週期」 | 沿用畫面上的「授權有效」 |

### 6. 輸出

- 指定路徑 → 寫入該 markdown。
- 未指定 → 寫在對話中。
- 一個指定範圍一篇；不要自行切成多段，除非使用者要求。

## 輸出格式

每篇 **只准**這三個內容區塊（區塊標題用詞固定）。段前 `##` 用一句畫面摘要。

```markdown
## （一句畫面摘要。不要貼檔名、函數名、或指定文件原標題。）

### 使用者操作目的
（2–4 句。誰、在哪個畫面、想完成什麼。不要寫重構／API／收斂。）

### 使用者操作流程
1. （單一動作：進入哪個畫面或打開哪個畫面）
2. （單一動作：點選、篩選、或送出）
3. （單一動作：畫面上出現什麼結果）

### 相關聯的畫面
- （從程式碼觀察到的畫面／分頁名，原樣列出）
```

流程規則：

- 用編號步驟；一步一個動作。
- 步驟裡的畫面名必須寫成「{名稱} 分頁」或「{名稱} 畫面」，不可只寫名稱。
- 講該畫面裡的清單時寫「{名稱} 分頁的表格」；講欄時寫「{名稱} 分頁的表格，{欄} 欄」。
- 只寫指定程式碼實際覆蓋的路徑；不要為了「完整」補沒讀到的步驟。
- 多個畫面時，流程寫清楚各步驟落在哪個畫面；不要假裝只有一條路。

畫面規則：

- 「相關聯的畫面」每行一個名稱，與畫面標籤一致。
- 目的與流程正文禁止「{畫面} 的」所有格。
- 沒證據的畫面不要列。

不要加這些額外標題：名詞說明、未決問題、現行 API。缺證據就不要寫那句。

## Example

**不合格**（帶實作詞、自創詞、畫面用元件名、把範圍外行為捲進來）：

```
## applyLicenseFilter() 把 ACTIVE 授權寫入篩選集合

### 使用者操作目的
收斂 compound filter，讓 FE 的 applyLicenseFilter 改由 Inventory API 下發。

### 使用者操作流程
1. 呼叫 QueryOrgInventoryV15
2. 執行 applyLicenseFilter()

### 相關聯的畫面
- inv-device-list
```

**合格**（標題與正文都只用畫面詞；事實來自指定範圍的清單篩選程式碼）：

```
## 使用 Gold Security Pack 的裝置可被 NCC license、Nebula Professional Pack、Secure WiFi 篩選找到

### 使用者操作目的
在 Devices 分頁的表格用授權狀態篩選裝置時，使用 Gold Security Pack 的裝置要能被 NCC license、Nebula Professional Pack、Secure WiFi 的篩選條件找到。

### 使用者操作流程
1. 進入 License & inventory，打開 Devices 分頁
2. 在 Devices 分頁的表格選擇 License type 與 License state
3. Devices 分頁的表格顯示符合該 License type 與 License state 的裝置；使用 Gold Security Pack 而被算進該條件的裝置一併顯示

### 相關聯的畫面
- Devices
```

畫面上寫 Gold Security Pack、NCC license 就用那些詞；不要改成「複合篩選狀態」。指定範圍沒覆蓋到的行為不要寫。

## 交件前 Checklist

交件前逐項確認（標題與三區塊都要過）：

```
- [ ] 證據鏈完整：指定範圍 → 已讀使用者指出的程式碼
- [ ] 沒有只根據指定文件、標題或註解寫用途
- [ ] 沒有把範圍外的兄弟行為寫進來
- [ ] 指定文件與程式碼衝突時已跟程式碼；正文沒有差異表
- [ ] 標題已去實作化：無 API／函數／欄位／enum；不是檔名或文件原標題
- [ ] 標題與正文無當前 API 端點／方法／欄位路徑／payload
- [ ] 標題與正文無函數名、變數名、元件名、檔案路徑、enum／常數字面值
- [ ] 標題與正文無自創專有名詞；產品詞可在畫面或該範圍 i18n 對到
- [ ] 「使用者操作目的」是畫面目標，不是重構／Consume／映射動機
- [ ] 三個區塊齊全，且沒有多出其他標題
- [ ] 相關聯的畫面來自程式碼觀察，不是預設清單，且可被掛載位置支持
- [ ] 流程每步都是使用者動作或可觀察結果
- [ ] 標題與正文無「等等」「等」「同上」「類似」「之類」用來省略項目；清單已寫完整
- [ ] 標題與正文無「用得上」口語；動作使用接受、使用、選擇、篩選、顯示、進入、點選
- [ ] 畫面名未寫成「{畫面} 的」所有格；已寫「{畫面} 分頁的表格」或「{畫面} 分頁的表格，◯◯ 欄」
```
